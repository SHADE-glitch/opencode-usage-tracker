# ocut — read-only audit report (2026-10-26)

> **A snapshot, not current state.** One-off read-only audit of
> `opencode-usage-tracker` at `8b91324`, taken on 2026-10-26: full source reading, probes on
> copies of the host database under `/tmp`, and a full test run. Nothing was installed and no
> repository file was modified during the audit. Repaired items carry **fixed in `<commit>`**;
> open ones are listed at the end.

- **Baseline**: `.venv/bin/python -m pytest scripts/tests -q` → **484 passed** (244 s). 383 was a
  pre-2026-10-22 number; the `test_cross_repo_golden.py` file added on 2026-10-25 accounts for most
  of the difference.
- **Verdict**: the read-only path, the window arithmetic and the "NULL is not zero" rendering are
  sound. The failures are at the two edges of the sync: **what the parser silently skips**, and
  **what the cursor does when it moves backwards**.

### Evidence for the P1s

1. **Dropped v2 turn.** Two v2 assistant messages, one completed without tokens: `model_calls`
   held only the healthy one, `unparsed` was empty, and the cursor sat at 2 — the turn could never
   be revisited. v1 has counted this shape as `step_finish_without_tokens` all along.
2. **JSONC.** The same fixture with and without one trailing comment: with it, `mcp_usage` 0 rows,
   the attributed call classified `builtin`, and `plugin_surface` empty; without it, 1 row and two
   plugin surfaces. Nothing was logged in `unparsed` either way.
3. **Held cursor.** One running tool plus two unknown part types, three consecutive syncs:
   `unparsed` went 2 → 4 → 6 while the cursor never moved. The TUI syncs on every start, so the
   count grew with every window opened.

## 2. Verified clean

- **Read-only**: the host database is opened `mode=ro` with `PRAGMA query_only`; no code path
  writes it.
- **Windows**: half-open `[start, end)` on whole local calendar days, computed in one place.
- **Unknown vs zero**: token, cost and duration columns keep NULL; `fmt_n`/`fmt_cost`/`ms` render
  `-`. The one exception was finding 9.
- **SQL**: values are bound; identifiers come from literals.
- **Documents**: the 14 headless subcommands in the README match argparse; the maintenance
  documents are generated from the code and the check passes.

## 3. Standards deviations found (fixed)

Four comments described a different build: the `q_mcp` join, the plugin-name CTE filter, a "TUI
calls this every 30 seconds" that the TUI never does, and the `o` key that is actually `s`
(`202ae8f`). Four queries had no caller outside the tests and were removed (`1a3cdb0`); a
`_hermetic` branch that cannot run in this repo was deleted and the suite's config path pinned
(`9f00aae`).

## 4. Open after this round

- A transcript truncated exactly at a legal JSON prefix (`{"type":"assistant"}`) would be consumed
  as a whole record; the tail strategy assumes that cannot happen.
- `ensure_schema` rebuilds views with DDL on every sync; with a large database and a lock wait
  longer than the timeout, a second process can still fail — now with a message instead of a
  traceback.
- `qcut restore`-style backup handling while a TUI holds the database was not exercised.
- The plugin-events cursor is a text-mode `tell()` compared against `st_size`; UTF-8 makes them
  agree today, but a half-character tail would be swallowed.
- A `LIKE '%'||?||'%'` in the request-log query does not escape wildcards (the TUI input does not
  filter them either).
