# OpenCode interface dependency list

Every place this project touches OpenCode, one row per dependency, with what happens if
the host changes it. Generated by reading `scripts/ocut-sync.py`'s format registry and
`plugin/ocut-hook.js` — not from memory. If you add a dependency, add its row here **and**
its declaration in the registry (or the hook) in the same commit; `ocut format` prints the
registry so it cannot describe a surface the code no longer reads, and
`scripts/tests/test_ocut_sync.py` locks both directions.

Legend — **blast radius**: `silent` = keeps running, records nothing (the worst kind);
`loud` = raises, refuses to start, or `ocut health` says so; `cosmetic` = a number or label
is wrong but the data is fine.

---

## 1. The host database

Opened `mode=ro` with `PRAGMA query_only = ON`; a missing file raises. Never written.

| Table | What we take from it | Writes to | If it disappears |
|---|---|---|---|
| `part` | `type`, and for a `tool` part its `tool` name and `state` (`status`, `input`, `time`); for a `step-finish` part its `reason`, `cost` and `tokens` | `tool_calls`, `skill_usage`, `agent_usage`, `mcp_usage`, `model_calls` | silent — no usage rows at all; the run still prints "done" |
| `message` | the model behind a step (`modelID`, `providerID`, `variant`, `agent`) | `model_calls.model` / `.provider` / `.variant` / `.agent` | cosmetic — those columns go NULL |
| `session` | the session's project, directory, agent, model, parent and the host's own cost/token rollup | `sessions` | silent — no session rows, so the dashboard's Sessions/Projects read 0 |

Two things a passive reader cannot see and does not pretend to: a plugin's identity behind
a tool call, and a plugin command at all. Both are the sidecar's job (§3).

## 2. The host config

| Path | Read or write | Declared as |
|---|---|---|
| `~/.config/opencode/` | read (config, plugin dir, skills, agents, commands) | `HOST_CONFIG_DIR` |
| `~/.config/opencode/opencode.json`, `.jsonc` | read — to find MCP servers, plugin specs and providers | a parse failure is **never** treated as "empty config" |
| `<config>/skills/**/SKILL.md` | read — frontmatter `name` and `version` only | the body is never opened |
| `<config>/agents/*.md`, `<config>/command/*.md` | read — the installed agent and command names | |
| `~/.cache/opencode/packages/` | read by the hook, to resolve a plugin spec to a file for its surface scan | `OCUT_HOOK_PACKAGES` |
| **`~/.config/opencode/**` is never written** | — | a hard rule: it is the host's, and the hook only ever appends to its own sidecar |

## 3. The plugin-usage sidecar (the one input that is ours)

OpenCode names no plugin behind a tool call and records nothing for a command, so
`plugin/ocut-hook.js` appends what it can attribute to a JSONL file this project owns.

| Record | Written when | Read by |
|---|---|---|
| `surface` | at hook load, one per installed plugin, from the static scan of its source | `ocut sync` → `plugin_surface`, folded into `inventory` |
| `call` | on a tool or command call the hook can attribute | `ocut sync` → `plugin_usage` |
| `reset` | when the hook truncates an oversized sidecar (8 MiB) | `ocut sync` (the truncation is also seen as `size < cursor`) |

The hook never opens OpenCode's database, never writes under `~/.config/opencode`, and
never reads a tool's arguments, output or any message text.

## 4. HTTP and subprocess edges

| Edge | Direction | Rule |
|---|---|---|
| `opencode --version` | out, a human runs it | the reader itself opens no socket; there is no telemetry, no update check, and no dependency that puts message content on disk |
| the hook's static scan | local file reads only | it reads plugin source to attribute a call; it never shells out and never reaches the network |

Nothing in this project opens a socket. `ocut sync`, the TUI and every report read local
files only.

## 5. Environment variables

The reader and the hook read, in one place each: `OCUT_DB`, `OCUT_OPENCODE_DATA`,
`OCUT_OPENCODE_CONFIG`, `OCUT_HOST_DB`, `OCUT_HOOK_EVENTS`, `OCUT_CONFIG`,
`XDG_CONFIG_HOME` (Python side); `OCUT_HOOK_DISABLE`, `OCUT_HOOK_EVENTS`,
`OCUT_HOOK_PACKAGES`, `OCUT_OPENCODE_CONFIG`, `HOME` (hook); `OCUT_SCRIPTS`,
`OCUT_VENV` (the launcher); `OCUT_CONFIG_DIR`, `OCUT_BIN_DIR` (the installer). They are
documented in README's environment table and in
[`MAINTENANCE.md`](../../MAINTENANCE.md) §0.

## 6. The hook export contract, because it is the one thing that can stop everything

`plugin/ocut-hook.js` must export **only** `export default { id, server }`. OpenCode
treats every exported function in a plugin module as a plugin factory and stops only when
the default export is an object carrying `server`; a named `export function` gets called as
a factory, which aborts the whole plugin load and stops plugin recording silently.
`scripts/tests/test_ocut_hook.py` keeps that true.
